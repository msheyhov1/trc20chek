# TRC20 Address Checker — Railway edition

Один сервис (FastAPI + Telegram-бот в одном процессе), готовый к деплою на Railway.

## Что внутри

- **REST API** (`FastAPI`): `GET /check/{address}`, `POST /check/batch`,
  `GET /history`, `GET /stats`, `GET /health`
- **Telegram-бот** — фоновой задачей того же процесса
- **Мониторинг адресов** — фоновая перепроверка с уведомлением при смене риска
- **Веб-форма** на корне `/` с постоянными ссылками и историей
- **SQLite на персистентном диске** (`/data`): кеш, кластеризация депозитников,
  журнал проверок, ручные метки, список наблюдения

### Что проверяется

| Источник | Что даёт |
|---|---|
| TronScan | публичные метки, тип аккаунта, баланс, возраст адреса, признаки токенов |
| Переводы TronScan | связи с биржами, экспозиция, депозитники, 2-й хоп |
| OFAC SDN | прямое попадание в санкционный список (все файлы фида, не только TRX) |
| Блэклист Tether | заблокированы ли средства эмитентом USDT |
| GoPlus | риск-флаги адреса |
| TronScan Security | безопасность контракта (для контрактов) |
| Swapster, Bitok | два независимых платных KYT |

Если источник недоступен, это видно в вердикте отдельной строкой: «нет находок»
и «не удалось проверить» — разные вещи.

## Деплой на Railway: по шагам

### 1. Загрузить код на GitHub

Создайте на GitHub пустой репозиторий, например `trc20-checker`. Затем локально:

```bash
cd trc20-checker
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ_USER/trc20-checker.git
git push -u origin main
```

### 2. Создать проект в Railway

1. Откройте <https://railway.app> → Sign in (через GitHub)
2. **New Project** → **Deploy from GitHub repo**
3. Выберите ваш `trc20-checker`
4. Railway автоматически найдёт `Dockerfile` и начнёт сборку

### 3. Добавить переменные окружения

В дашборде сервиса → **Variables** → **+ New Variable**:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | Токен от @BotFather (обязательно) |
| `ALLOWED_TG_IDS` | Белый список Telegram user_id — **обязательно**, пусто = бот закрыт для всех. Только цифры через запятую, без кавычек и без @username |
| `TRONSCAN_API_KEY` | (опционально) |
| `GOPLUS_API_KEY` | (опционально) |
| `API_KEY` | (опционально, защита API — заголовок `X-API-Key`) |
| `WEB_PUBLIC` | `1`, если сайт должен быть открыт всем. **Без пароля, ключа и этой переменной `/check` отвечает 503** |
| `WEB_PASSWORD` | (опционально) пароль на сайт |
| `TRONGRID_API_KEY` | (опционально) лимиты для проверки блэклиста Tether |
| `SWAPSTER_API_TOKEN` | Токен AML-сервиса Swapster (опционально) |
| `BITOK_API_KEY_ID` | API Key ID сервиса Bitok KYT (опционально) |
| `BITOK_API_SECRET` | API Secret сервиса Bitok KYT (опционально) |
| `CACHE_TTL_SECONDS` | `604800` |

Полный список переменных — в `.env.example`. Без AML-ключей сервис работает,
но в выводе будет «Swapster/Bitok не настроен».

**Важно про доступ.** У бота гейт fail-closed: пустой `ALLOWED_TG_IDS` не пускает
никого. Веб устроен так же: если не задан ни `WEB_PASSWORD`, ни `API_KEY`, ни
`WEB_PUBLIC=1`, эндпоинт `/check` отвечает 503. Причина — каждая проверка тратит
платные лимиты KYT, поэтому «открыт всем по умолчанию» недопустимо. Для открытого
доступа действуют лимиты на IP и суточная квота (`RATE_LIMIT_*`).

### 4. Добавить персистентный диск

Без него сервис поднимется, но выключатся кеш, кластеризация депозитников, журнал
проверок, ручные метки и мониторинг. Состояние видно в `/health` → `storage`.

В дашборде сервиса → **Settings** → **Volumes** → **+ New Volume**:
- **Mount path:** `/data`
- Размер: 1 GB (бесплатного хватит надолго)

После добавления Railway пересоберёт сервис.

### 5. Сделать API публично доступным

В **Settings** → **Networking** → **Generate Domain**.
Получите ссылку вида `https://trc20-checker-production.up.railway.app`.

### 6. Проверка

Откройте в браузере:
- `https://ваш-домен/health` — статус, сконфигурированные провайдеры, состояние
  хранилищ и лимиты
- `https://ваш-домен/` — веб-форма
- `https://ваш-домен/check/TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t` — проверка USDT-контракта

И напишите вашему боту в Telegram. Если `ALLOWED_TG_IDS` ещё не задан, бот ответит
отказом и покажет ваш Telegram ID — впишите его в `ALLOWED_TG_IDS` (Railway → Variables),
дождитесь передеплоя и напишите снова. Альтернатива — узнать ID у @userinfobot.

## Локальная разработка (опционально)

```bash
pip install -r requirements.txt
export BOT_TOKEN=  # можно пустым — будет API-only mode
export CACHE_PATH=./cache.db
uvicorn api.main:app --reload
```

## Тесты

```bash
pip install -r requirements.txt -r requirements-dev.txt

CACHE_PATH=./cache.db CLUSTER_PATH=./cluster.db HISTORY_PATH=./history.db \
LABELS_PATH=./labels.db WATCHLIST_PATH=./watchlist.db pytest -q

ruff check .
```

411 тестов, покрытие 87 %. CI (GitHub Actions) прогоняет линтер, тесты, покрытие и
сборку Docker-образа с проверкой, что контейнер отвечает на `/health`.

## Кастомизация

**Свои метки адресов — прямо из бота, без редеплоя:** `/label АДРЕС тип уровень
название`, `/unlabel`, `/labels`. Метки имеют наивысший приоритет в вердикте.
Предзаданные в `core/providers/local.py` засеваются в базу при старте.

**Список бирж:** `core/aggregator.py` → `EXCHANGE_KEYWORDS` (обычные),
`SANCTIONED_EXCHANGES` + `SANCTIONED_EXCHANGE_SOURCE` (санкционные), env
`HIGH_RISK_EXCHANGES` (обменники без KYC).

**Пороги эвристик** (депозитники, транзит, 2-й хоп, отравление истории) задаются
переменными окружения — см. `.env.example`.

## Команды бота

| Команда | Что делает |
|---|---|
| любой текст | проверка адреса; понимает пунктуацию, ссылки TronScan, hex `41…` |
| файл | пакетная проверка списка адресов |
| `/help` | справка: источники, форматы, команды |
| `/id` | свой Telegram ID для белого списка |
| `/status` | какие ключи и провайдеры сконфигурированы |
| `/history`, `/stats` | последние проверки и расход платных лимитов |
| `/label`, `/unlabel`, `/labels` | свои метки адресов |
| `/watch`, `/unwatch`, `/watchlist` | следить за адресом и узнать об изменении риска |
